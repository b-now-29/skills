## 하는 일

`wizard`는 사람에게 수동 절차를 단계별로 안내하는 대화형 bash 스크립트를 생성합니다. 서드파티 서비스 연결, 일회성 마이그레이션 실행, 프로젝트를 상태 A에서 상태 B로 옮기기 등입니다. 각 URL을 열고, 무엇을 클릭하고 복사해야 하는지 알려 주고, 돌아온 값을 받아, `.env` 파일과 GitHub Actions 시크릿에 기록합니다.

[에이전트](https://www.aihero.dev/ai-coding-dictionary/agent)는 스크립트를 작성하지만, 결코 실행하지 않습니다. 사용자가 자신의 머신에서 실행합니다. 마법사는 지시 목록이 아니라 프로그램입니다. 스크립트가 각 단계를 순서대로 실행하고 입력한 값을 보관합니다. 사용자의 몫은 클릭하고, 붙여 넣고, Enter를 누르는 것입니다.

## 언제 사용하는가

`/wizard`를 입력할 수 있으며, 에이전트가 스스로 사용할 수도 있습니다. 사용자가 해야 하는 단계(에이전트가 발급할 수 없는 키, 에이전트가 클릭할 수 없는 대시보드)에 부딪히면, 스크롤되어 사라지는 채팅에 지시를 쓰는 대신 마법사를 만들어 줍니다.

다음에 막고 있는 것이 대시보드를 거쳐 가는 일일 때 사용하십시오.

| 상황 | 마법사가 하는 일 |
| --- | --- |
| 새 개발자가 앱이 부팅되기 전에 여섯 개의 서비스를 구성해야 함 | 각 대시보드를 순서대로 열고, 키를 받아, `.env`와 CI에 기록함 |
| 일회성 마이그레이션에서 특정 순서로 스위치를 바꿔야 함 | 되돌릴 수 없는 단계를 확인 관문 뒤에 순서대로 배치함 |
| 프로젝트를 한 번 상태 A에서 상태 B로 옮겨야 함 | 전환을 안내하고 할 수 없었던 것을 보고함 |
| 그 단계들을 README에 쓰려는 참임 | 대신 실행 가능한 버전을 작성하며, 단계가 낡으면 눈에 보이게 실패함 |

무엇을 만들지 *결정하기* 위해서는 사용하지 마십시오. 그것에는 [grill-with-docs](https://aihero.dev/skills-grill-with-docs)와 [to-spec](https://aihero.dev/skills-to-spec)이 도구입니다.

## 사전 요구 사항

마법사를 생성하는 데는 아무것도 필요 없습니다. 작성되는 마법사는 bash에서 실행되며, 단계가 GitHub 시크릿이나 변수를 설정할 때 `gh`를 사용합니다. `gh`가 없거나 인증되지 않았더라도 실행은 실패하지 않습니다. 해당 단계는 경고를 표시하고, 마무리 요약이 직접 설정해야 할 것을 알려 줍니다.

## 단계 (Stages)

**단계(stage)**는 한 화면에서의 하나의 집중된 작업입니다. 스크립트는 단계 사이에 터미널을 지우므로, 화면을 넘치는 단계는 스크롤되어 사라진 부분을 잃게 됩니다. 단계는 의존성 순서로 작성하고 `TOTAL_STAGES`를 설정하며, 이것이 진행 상황 표시를 결정합니다.

[스킬](https://www.aihero.dev/ai-coding-dictionary/skill)은 스크립트를 작성하기 전에 절차의 범위를 정합니다. 무작정 묻는 대신 저장소를 읽습니다. `.env*`, `docker-compose*`, 프레임워크 구성, 그리고 `.github/workflows/`의 모든 `secrets.*` / `vars.*` 참조입니다. 그 참조 각각이 마법사가 만들어 내야 하는 값입니다. 그런 다음 확인을 위해 순서가 정해진 단계 목록을 보여 줍니다. 확인한 후에야 각 단계를 사람이 따르는 정확한 경로("대시보드 → Developers → API keys → Reveal test key → 복사")에 대응시킵니다. 현재 UI를 모르는 곳에서는 클릭을 지어내는 대신 사용자에게 묻거나 문서를 확인합니다.

받는 각 값에 대해, 범위 정하기가 그 값이 어디로 갈지 결정합니다.

| 목적지 | 경우 |
| --- | --- |
| `.env`만 | 로컬 개발에는 필요하지만, CI에는 필요 없음 |
| GitHub 시크릿 | CI가 읽으며, 민감한 값임 |
| GitHub 변수 | CI가 읽으며, 공개 값임 |
| `.env`와 시크릿 둘 다 | 로컬 개발과 CI 모두 필요함 |
| 어디에도 없음 | 단계가 순수한 작업임: 스위치 변경, 요금제 업그레이드 |

## 템플릿이 이미 UX를 해결했다

[템플릿](https://github.com/mattpocock/skills/blob/main/skills/engineering/wizard/template.sh)이 전체 경험을 제공합니다. 남은 시간이 표시되는 진행 상황, 확인 관문, WSL을 포함한 크로스 플랫폼 URL 열기, 시크릿의 숨겨진 입력, 멱등적인 `.env` upsert, `gh secret` / `gh variable` 쓰기, 그리고 건너뛰어야 했던 모든 것에 대한 마무리 요약입니다. `STAGES` 표시 위의 모든 것은 고정된 라이브러리로, 모든 마법사에서 동일하며 결코 손으로 편집하지 않습니다. 라이브러리가 결코 바뀌지 않으므로, 모든 마법사가 같은 방식으로 동작합니다. 마법사마다 해야 할 일은 절차의 범위를 정하고 그 단계들을 작성하는 것뿐입니다.

마법사를 작성하는 에이전트는 결코 처음부터 끝까지 실행하지 않습니다. 스크립트가 브라우저를 열고 사람의 입력을 기다리기 때문입니다. 대신 에이전트는 정적으로 확인합니다. `bash -n`, 가능하다면 `shellcheck`, 그리고 모든 값이 범위 정하기에서 말한 곳에 기록되며 모든 `set_secret` 이름이 CI의 실제 `secrets.*` 참조와 일치하는지에 대한 추적입니다. 따라서 첫 실행은 사용자의 몫이며, 그 실행이 곧 테스트입니다.

## 기본적으로 일시적

| 가지고 있는 것 | 스크립트로 할 일 |
| --- | --- |
| 일회성 마이그레이션, 개인 설정, 다시 반복하지 않을 전환 | 임시 경로나 `scripts/` 경로에 저장하고, 실행한 다음, 삭제 |
| 저장소의 다음 사람도 필요로 할 설정 경로 | 커밋하고 README에서 링크하여, 그들이 에이전트에게 다시 묻는 대신 스크립트를 실행하도록 함 |

## 자주 묻는 질문

**제 API 키가 모델의 컨텍스트에 들어갑니까?**

아니요. 에이전트는 스크립트를 작성할 뿐, 실행하지 않습니다. 사용자가 직접 스크립트를 실행하며, 스크립트는 숨겨진 터미널 입력으로 키를 받아 바로 `.env`나 `gh secret`에 기록합니다. 마법사는 CLI이며, 모델은 그것에 연결되어 있지 않습니다. 이는 마법사가 실행 시점에 받는 값에만 해당합니다. 절차의 범위를 정하는 동안 채팅에 키를 붙여 넣는다면, 그것은 다른 붙여 넣은 텍스트와 마찬가지로 [컨텍스트](https://www.aihero.dev/ai-coding-dictionary/context)에 들어갑니다.

**잘못 입력한 값을 되돌아가서 고칠 수 있습니까?**

실행 도중에는 아닙니다. 뒤로 가기 버튼이 없습니다. 단계는 앞으로만 진행되며, 3단계에서 잘못 답했다면 Ctrl-C를 누르고 다시 실행해야 합니다. 다시 실행하는 비용은 적습니다. 이미 `.env`에 기록된 값은 기본값으로 다시 제시되므로, 맞게 입력한 단계는 Enter로 넘어가고 잘못된 것만 다시 입력하면 됩니다. 사용자들은 출시 주간에 이를 요청했으며, 아직 열려 있습니다. "정말 좋았어요! 그런데 한 가지, 입력한 것을 되돌아가서 고칠 방법이 있나요?"

**이미 설정한 것을 압니까?**

부분적으로만 알며, 출시 당시의 반응이 가정한 것보다는 적게 압니다. 묻기 전에 저장소(`.env` 파일, `docker-compose`, 프레임워크 구성, CI의 `secrets.*` 참조)를 읽으므로, README처럼 처음부터 시작하는 대신 빠진 값으로 범위를 정합니다. 서드파티 서비스는 확인하지 않습니다. 키가 `.env`에 있다면 마법사가 이를 다시 제시하고 Enter로 유지되지만, Stripe 계정은 이미 만들었는데 키를 저장하지 않았다면, 마법사는 여전히 키를 얻으러 대시보드로 보냅니다.

**워크플로에서 어디에 위치합니까? 그릴링과 명세 다음입니까?**

특별히 정해진 곳은 없습니다. 연쇄의 단계가 아니라 독립형입니다. 흔한 추측은 `/grill-with-docs → /to-spec → /wizard`이며, 그 순서도 괜찮지만, 트리거는 수동 절차가 등장하는 것이고, 그것은 언제든 일어날 수 있습니다. 시작하기 전, 구현 도중, 또는 출시 한참 후입니다. 발견 도구로도 동작합니다. 범위 정하기는 작업에 착수하기 전에 생각하지 못했던 세 개의 API 키처럼 작업의 숨겨진 전제 조건을 찾아냅니다.

**Claude Code 밖에서도 동작합니까?**

스크립트는 동작합니다. 평범한 bash이며, 어떤 [하네스](https://www.aihero.dev/ai-coding-dictionary/harness)가 생성했든 똑같이 실행됩니다. 스킬 자체는 모델 호출이므로 어디서나 나열됩니다. Claude Code에서는 `/wizard`를, Codex에서는 `$wizard`를 입력하거나, 막혀 있는 설정을 그냥 설명하십시오. 모델 호출이라는 점은 Claude의 데스크톱 및 웹 앱이 *사용자 호출* 스킬을 [모델](https://www.aihero.dev/ai-coding-dictionary/model)의 목록에서 누락하고 설치되지 않았다고 보고하는 [#693](https://github.com/mattpocock/skills/issues/693) 문제도 피하게 해 줍니다.

**예전에는 사용자 호출 아니었습니까?**

그랬습니다. 이제는 모델 호출이므로, 에이전트가 사용자가 해야 하는 단계에 부딪히면 지시 없이도 이를 사용합니다. 이전에 할 수 있던 것은 아무것도 멈추지 않았습니다. 모델 호출은 사용자뿐만 아니라 에이전트도 스킬을 호출할 수 있게 하므로, `/wizard`는 이전과 같이 동작합니다. 이 변경은 하나의 실패를 고칩니다. 이전에는 구현 도중 자격 증명의 벽에 부딪힌 에이전트가 사용자가 직접 따라 할 여섯 개의 번호 매긴 단계를 채팅에 쏟아 냈습니다. 이제는 마법사를 작성합니다.

**예전에는 `in-progress/`에 있었습니다. 지금은 어디에 있습니까?**

v1.2부터 `engineering/`에 있습니다. 베타 버킷에서 졸업하여 이제 플러그인에 포함되어 배포되므로, 개별 설치 없이 승격된 세트의 나머지와 함께 도착합니다. 졸업하면서 동작은 바뀌지 않았습니다.

## 제대로 동작하고 있다면

- 스크립트가 존재하기 전에, 순서가 정해진 단계 목록과 각 단계가 만들어 내는 값을 보여 주고 확인을 요청받습니다.
- 모든 URL이 해당 페이지의 값을 묻기 전에 열립니다. 가져오라고 보내지 않은 것을 붙여 넣으라는 요청은 결코 받지 않습니다.
- 시크릿은 보이지 않게 입력됩니다. 민감한 것이 스크롤 기록에 표시되지 않습니다.
- 각 단계가 한 화면에 들어갑니다. 아직 필요한 것이 스크롤되어 사라지지 않습니다.
- Ctrl-C를 누르고 다시 실행하면 중단한 곳부터 이어지며, 이미 저장된 값을 기본값으로 제시합니다.
- 마지막 화면이 기록한 것을 나열하고, 할 수 없었기 때문에 직접 마무리해야 하는 것을 따로 나열합니다.

## 어디에 위치하는가

`wizard`는 자동화가 멈추고 사람이 클릭해야 하는 경계에 있는, 언제든 사용할 수 있는 독립형 스킬입니다. 가장 가까운 이웃은 [setup-matt-pocock-skills](https://aihero.dev/skills-setup-matt-pocock-skills)입니다. 둘 다 저장소를 동작하는 상태로 만들기 위해 존재하기 때문입니다. 그 스킬은 이 스킬 세트를 구성하고, `wizard`는 그 밖의 모든 것을 위한 설정 경로를 생성합니다. [implement](https://aihero.dev/skills-implement)와도 짝을 이룹니다. 구현이 자격 증명이나 수동 전환이 필요한 기능을 반영할 때, 마법사가 사람만이 할 수 있는 단계를 다룹니다. 그 순간에 어떤 스킬이 맞는지 확실하지 않다면, [ask-matt](https://aihero.dev/skills-ask-matt)가 안내합니다.
