## 하는 일

`research`는 답을 소유한 자료를 읽어 질문에 답한 다음, 출처가 명시된 마크다운 파일을 저장소에 남깁니다. 오직 **[1차 자료](https://www.aihero.dev/ai-coding-dictionary/primary-source)**만으로 작업합니다. 공식 문서, 소스 코드, 명세, 퍼스트 파티 API입니다. 모든 주장을 그것을 소유한 출처까지 추적하므로, API 자체의 문서에 접근할 수 있는데 블로그 게시물의 API 설명을 반복하지 않습니다.

대화로 답하지 않습니다. 출력은 저장소가 이미 그러한 노트를 보관하는 곳에 작성되는 파일이며, 각 주장에 링크가 있습니다. [세션](https://www.aihero.dev/ai-coding-dictionary/session)이 끝나면 사라지는 답이 아니라, 반응하거나, 다른 에이전트에게 건네거나, 버릴 수 있는 문서를 얻게 됩니다.

## 언제 사용하는가

`/research`를 입력하거나, 작업이 읽는 발품으로 바뀔 때 [에이전트](https://www.aihero.dev/ai-coding-dictionary/agent)가 자동으로 사용합니다.

다음 단계가 작업 디렉터리 밖에서 *무언가를 알아내는 것*(서드파티 API가 어떻게 동작하는지, 명세가 무엇을 말하는지, 버전에 관한 주장이 맞는지)이고, 직접 읽느라 자신의 스레드를 멈추고 싶지 않을 때 사용하십시오. 무엇이 필요한지가 어떤 스킬을 쓸지 결정합니다.

| 필요한 것 | 사용할 것 |
| --- | --- |
| 결정이 기다리고 있는 외부 사실 | `research` |
| 인터뷰를 통해 사용자와 *함께* 내리는 결정 | [grilling](https://aihero.dev/skills-grilling) |
| `GLOSSARY.md`와 ADR에 기록되는 지속적인 아키텍처 결정 | [grill-with-docs](https://aihero.dev/skills-grill-with-docs) |
| 어떤 접근 방식이 코드베이스에서 동작하는지 알아내기 | [prototype](https://aihero.dev/skills-prototype) |
| 한 세션에 담기에 너무 큰 계획 | [wayfinder](https://aihero.dev/skills-wayfinder) |

`research`와 `grill-with-docs` 사이의 경계는 **돌아오는 것의 유통 기한**입니다. 조사는 수명이 짧은 사실을 만들어 냅니다. 예를 들어 이번 주 기준으로 이 라이브러리의 인증 방식이 무엇을 하는지입니다. ADR은 보관하는 결정을 기록합니다. 만들어 내는 것이 사실이 아니라 결정이라면, 조사하는 것이 아니라 [그릴링](https://www.aihero.dev/ai-coding-dictionary/grilling)하는 것입니다.

## 위임된 발품

읽기는 **백그라운드 에이전트**로 실행됩니다. 에이전트가 각 주장을 1차 자료까지 추적하고, 하나의 마크다운 파일을 작성하고, 보고하는 동안 사용자는 계속 작업합니다. 조사는 외주를 주는 사고가 아니라 위임하는 발품입니다. 그릴링하거나, 계획하거나, 설계할 기준이 되는 문서를 얻으며, 결정은 여전히 사용자가 합니다.

백그라운드 에이전트가 자신의 백그라운드 에이전트를 또 생성하는 것을 막는 것은 없습니다. 이것이 이 스킬에서 가장 잘 문서화된 문제입니다.

파일이 어디로 갈지는 스킬이 아니라 저장소가 결정합니다. 노트에 대해 이미 존재하는 관례를 따릅니다. 관례가 없다면, 합리적인 곳을 골라 어디인지 알려 줍니다. 실행당 하나의 파일을 작성합니다.

## 자주 묻는 질문

**두 번째 조사 에이전트를 생성했습니다. 원래 그래야 합니까?**

아니요. 이것은 열려 있는 버그입니다([issue #530](https://github.com/mattpocock/skills/issues/530)). 스킬은 호출자에게 백그라운드 에이전트를 띄우라고 지시하지만 에이전트 유형을 제한하지 않습니다. 그래서 호출자는 `Agent` 도구와 같은 지시를 가진 `general-purpose` 에이전트를 생성하고, 그 에이전트는 지시를 다시 따릅니다. 한 보고자는 단일 조사 작업이 세 번의 겹치는 실행에 걸쳐 약 450k [토큰](https://www.aihero.dev/ai-coding-dictionary/token)을 소비했으며, 중복 실행은 사용자가 볼 수 없는 곳에서 30분 후에 끝났다고 측정했습니다. Claude Code 밖에서도 일어납니다. 사용자들은 GPT-5.6-sol을 사용하는 Codex에서도 같은 중첩을 확인했습니다. 배포된 수정은 없습니다. 사용자들은 이미 [서브에이전트](https://www.aihero.dev/ai-coding-dictionary/subagent)인 에이전트에게 직접 작업하라고 지시하는 한 줄로 설치된 사본을 패치했습니다. 도움은 되지만, 구조적인 수정이 아니라 지시일 뿐입니다. 스킬을 호출한 후 백그라운드 작업 목록을 지켜보고 중복을 중단하십시오.

반대의 실패도 일어납니다. 사용자의 전역 지시가 에이전트의 재위임을 금지한다면, 백그라운드 에이전트는 작업을 거부하며, 스킬은 알리지 않은 채 아무것도 하지 않습니다.

**파일은 어디에 두어야 하며, 커밋해야 합니까?**

스킬은 저장소가 이미 노트를 보관하는 곳에 파일을 두며, 그 이상의 의견은 없습니다. 커뮤니티의 견해는 대체로 정리되어 있습니다. ADR은 보관하고, 조사 파일은 보관하지 않는 것입니다. 이 질문에 대한 한 Discord 스레드가 가장 명확하게 말했습니다. "ADR은 예. 그 외의 모든 것은 완료 후 보관하거나 삭제하라. 그렇지 않으면 작업의 찌꺼기가 되며, 명세/조사에서 벗어났다면 향후 저장소 읽기를 오염시킬 수 있다." 조사 파일은 작성된 날에 참이었던 것을 기록하므로, 낡은 파일은 없는 것보다 나쁩니다. 종합하면, 이러한 파일은 git에 속하지 않으며, 표준적인 거처도 없습니다. 사람들은 대신 Obsidian, 별도의 지식 저장소, 또는 이슈 트래커를 사용합니다.

**무엇이 "신뢰도 높은" 1차 자료로 인정되며, 누가 결정합니까?**

[모델](https://www.aihero.dev/ai-coding-dictionary/model)이 결정합니다. 스킬은 인정되는 자료의 *종류*(공식 문서, 소스 코드, 명세, 퍼스트 파티 API)를 명시하지만, 허용 목록도, 도메인 관문도, 검증 단계도 없습니다. 이것은 스킬이 처음 제안되었을 때 가장 큰 반론이었으며, 아무도 공개적으로 답하지 않았습니다. "엉터리 자료를 가리키는 다섯 개의 조사 서브에이전트는 다섯 개의 자신만만한 오답을 더 빨리 줄 뿐이다. 무엇이 신뢰도 높은 자료인지 어떻게 관문을 두는가?" 유일한 보호 장치는 각 주장의 인용입니다. 두세 개를 따라가 보십시오. 그것들이 대상 자체가 아니라 대상의 요약에 도달한다면, 실행은 실패한 것입니다.

**이후 세션이 이전 실행에서 발견한 것을 재사용합니까?**

아니요. 과거 조사 파일을 자동으로 로드하는 것은 없습니다. 사람이나 스킬이 가리킬 때까지 파일은 저장소에 머무릅니다. 이것이 설계에 대한 가장 강력한 초기 반론이었습니다. "가치는 가져오기 자체가 아니라, 마크다운이 에이전트가 나중에 다시 읽는 컨텍스트가 되는 데 있다. 한 번 쓰고 마는 죽은 파일은 그저 화려한 검색일 뿐이다." 배포된 스킬은 이를 해결하지 않습니다. 실제로 파일은 다음 단계에 직접 넣을 때만 유용합니다. 명세에 첨부하거나, 그릴링 세션에 인용하거나, [티켓](https://www.aihero.dev/ai-coding-dictionary/ticket)이 그것을 가리키게 하십시오.

**그냥 에이전트에게 문서를 읽으러 가라고 하면 안 됩니까?**

그럴 수 있으며, 정확히 그렇게 말하는 두 줄짜리 프롬프트가 이 스킬이 대체한 관행이었습니다. 스킬은 프롬프트가 주지 않는 두 가지를 줍니다. 백그라운드에서 실행되므로 세션의 [컨텍스트](https://www.aihero.dev/ai-coding-dictionary/context)가 깨끗하게 유지됩니다. 그리고 1차 자료 제약과 출처가 명시된 파일 출력이 프롬프트를 어떻게 표현했는지에 따라 달라지지 않고 매번 같습니다. [하네스](https://www.aihero.dev/ai-coding-dictionary/harness) 자체의 심층 조사 모드와 비교하면, 차이는 검색이 아니라 파일과 1차 자료 규칙입니다. 작은 질문에서 두 줄짜리 프롬프트로 필요한 것을 얻을 수 있다면, 두 줄짜리 프롬프트를 사용하십시오.

**언제 읽기를 멈춥니까?**

스킬에는 중단 기준이 없습니다. 이는 반대로 보이지만 원인이 같은 두 가지 불만으로 나타납니다. 너무 깊이 들어가는 에이전트, 그리고 주제를 넓게 다루지만 중요했던 하나의 세부 사항을 놓치는 에이전트입니다. 한 실무자는 이렇게 말했습니다. "심층 조사 스킬은 때때로 너무 깊다. 그리고 에이전트에게 조사하라고 하면 대개 결정적인 세부 사항을 놓친다." 범위는 사용자가 정해야 합니다. 좁고 답할 수 있는 질문(하나의 API, 하나의 동작, 하나의 버전 주장)이 "X를 조사하라"보다 훨씬 나은 결과를 가져옵니다.

**`/wayfinder`가 조사 티켓을 만들었습니다. 그것들을 직접 해결해야 합니까?**

아니요, 이제 대신 실행해 줍니다. v1.1 이후의 미배포 변경에서, 지도 그리기 세션은 조사 티켓마다 하나의 `/research` 서브에이전트를 생성하여 병렬로 실행합니다. 각각은 일회용 `research/<name>` 브랜치에 결과를 기록하며, 티켓에서 [컨텍스트 포인터](https://www.aihero.dev/ai-coding-dictionary/context-pointer)로 가리킵니다. 조사 티켓은 wayfinder의 세션당 티켓 하나 규칙의 유일한 예외입니다. [AFK](https://www.aihero.dev/ai-coding-dictionary/afk)이기 때문입니다. 사용자를 기다리는 것이 없습니다. 알려진 문제 하나: 나중에 브랜치를 삭제하면 티켓의 컨텍스트 포인터가 깨집니다.

## 제대로 동작하고 있다면

- 자신의 세션이 계속 진행됩니다. 앉아서 에이전트가 읽는 것을 지켜보고 있다면, 위임이 일어나지 않은 것입니다.
- 정확히 하나의 새로운 백그라운드 작업이 나타납니다. 거의 같은 이름의 두 번째 작업은 중첩 버그입니다.
- 저장소가 이미 노트에 사용하는 폴더에 하나의 새로운 마크다운 파일이 나타나며, 에이전트가 경로를 알려 줍니다.
- 그 안의 모든 주장에 링크가 있으며, 무작위로 두 개를 따라가면 누군가의 정리가 아니라 공식 문서, 명세, 또는 소스 파일 자체에 도달합니다.
- 직접 자료로 돌아가지 않고도 파일만으로 막혀 있던 결정을 내릴 수 있습니다.

## 어디에 위치하는가

`research`는 언제든 사용할 수 있는 독립형 스킬입니다. 사고하는 스킬에 재료를 공급하며 구현 연쇄의 한 단계가 아닙니다. 그 파일을 흐름 *안으로* 가져갑니다. [grilling](https://aihero.dev/skills-grilling)과 [grill-with-docs](https://aihero.dev/skills-grill-with-docs)는 이미 사실을 가지고 있을 때 더 날카로운 질문을 하며, [to-spec](https://aihero.dev/skills-to-spec)은 그것을 기준으로 종합할 수 있습니다. [wayfinder](https://aihero.dev/skills-wayfinder)는 이를 직접 호출하는 유일한 스킬입니다. 지도의 각 조사 티켓을 `/research` 서브에이전트로 해결합니다. 전체 지도는 [ask-matt](https://aihero.dev/skills-ask-matt)를 참조하십시오.
