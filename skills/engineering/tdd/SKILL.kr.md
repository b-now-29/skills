# 테스트 주도 개발

TDD는 red → green 루프입니다. 이 스킬은 그 루프가 보존할 가치가 있는 테스트를 만들어 내도록 하는 참조입니다. 좋은 테스트란 무엇인지, 테스트를 어디에 두는지, 안티 패턴, 그리고 루프의 규칙을 다룹니다. 모든 섹션은 매 사이클에 적용됩니다. 루프가 끝난 후가 아니라, 루프 전과 루프 중에 참고하십시오.

코드베이스를 탐색할 때, 테스트 이름과 인터페이스 어휘가 프로젝트의 도메인 언어와 일치하도록 `GLOSSARY.md`(있는 경우)를 읽고, 작업 중인 영역의 ADR을 존중하십시오.

## 좋은 테스트란 무엇인가

테스트는 구현 세부 사항이 아니라 공개 인터페이스를 통해 동작을 검증합니다. 코드는 완전히 바뀔 수 있지만, 테스트는 바뀌지 않아야 합니다. 좋은 테스트는 명세처럼 읽힙니다. "사용자는 유효한 장바구니로 결제할 수 있다"는 어떤 기능이 존재하는지 정확히 알려 주며, 내부 구조에 신경 쓰지 않으므로 리팩터링에도 살아남습니다.

예시는 [tests.md](tests.md)를, 목(mock) 지침은 [mocking.md](mocking.md)를 참조하십시오.

## 시임: 테스트를 두는 곳

**시임(seam)**은 테스트하는 공개 경계입니다. 내부로 손을 뻗지 않고 동작을 관찰하는 인터페이스입니다. 테스트는 시임에 위치하며, 결코 내부를 대상으로 하지 않습니다.

**사전에 합의된 시임에서만 테스트하십시오.** 어떤 테스트든 작성하기 전에, 테스트할 시임을 적고 사용자와 확인하십시오. 확인되지 않은 시임에서는 어떤 테스트도 작성하지 않습니다. 모든 것을 테스트할 수는 없으므로, 시임을 미리 합의하는 것이 테스트 노력이 모든 엣지 케이스가 아니라 중요한 경로와 복잡한 로직에 집중되도록 하는 방법입니다.

다음을 물으십시오. "공개 인터페이스는 무엇이며, 어떤 시임을 테스트해야 하는가?" 제안하는 각 시임에 그것이 무엇을 잡아내고 무엇을 놓치는지에 대한 한 줄 메모를 덧붙이십시오.

그 인터페이스의 형태 자체가 문제가 될 때(모듈이 얼마나 깊은지, 시임이 어디에 속하는지, 인터페이스가 무엇을 노출해야 하는지), 어휘를 위해 "codebase-design"으로 Skill 도구를 호출하십시오. 이 스킬은 module, interface, depth, seam, adapter, leverage, locality 용어의 공유 출처이며, 실행할 세션이 아니라 참고할 참조입니다.

## 안티 패턴

- **구현에 결합됨**: 내부 협력자를 목으로 대체하거나, private 메서드를 테스트하거나, 우회 경로를 통해 검증합니다(인터페이스를 사용하는 대신 데이터베이스를 조회). 징후: 동작은 바뀌지 않았는데 리팩터링하면 테스트가 깨집니다.
- **동어 반복적**: 단언이 코드가 하는 방식대로 기대값을 다시 계산하므로(`expect(add(a, b)).toBe(a + b)`, 같은 방식으로 손으로 도출한 스냅샷, 자기 자신과 같다고 단언된 상수), 구조적으로 통과하며 코드와 결코 의견이 다를 수 없습니다. 기대값은 독립적인 진실 공급원에서 와야 합니다. 알려진 정상 리터럴, 손으로 풀어 본 예시, 명세입니다.
- **수평 슬라이싱**: 모든 테스트를 먼저 작성한 다음, 모든 구현을 작성하는 것. 일괄 작성된 테스트는 _상상한_ 동작을 검증합니다. 사용자가 보는 동작이 아니라 사물의 _형태_를 테스트하게 되고, 테스트는 실제 변경에 둔감해지며, 구현을 이해하기 전에 테스트 구조를 확정하게 됩니다. 대신 **수직 슬라이스**로 작업하십시오. 테스트 하나 → 구현 하나 → 반복이며, 각 테스트는 이전 사이클이 가르쳐 준 것에 반응하는 **트레이서 불릿(tracer bullet)**입니다.

## 루프의 규칙

- **green 전에 red.** 실패하는 테스트를 먼저 작성한 다음, 그것을 통과시킬 만큼의 코드만 작성하십시오. 미래의 테스트를 예상하거나 추측성 기능을 추가하지 마십시오.
- **한 번에 하나의 슬라이스.** 사이클당 하나의 시임, 하나의 테스트, 하나의 최소 구현입니다.
- **리팩터링은 루프의 일부가 아닙니다.** 리팩터링은 red → green 구현 사이클이 아니라 리뷰 단계(`code-review` 스킬 참조)에 속합니다.
