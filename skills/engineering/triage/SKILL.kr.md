# 트리아지

프로젝트 이슈 트래커의 이슈를 트리아지 역할로 이루어진 작은 상태 기계를 따라 이동시키십시오.

이 저장소가 외부 풀 리퀘스트를 요청 창구로 취급한다면(이슈 트래커 구성 참조), 트리아지는 PR도 다룹니다. **PR은 코드가 첨부된 이슈**이며, 같은 역할, 같은 상태, 같은 기계를 사용하고, 아래에 "PR의 경우"로 표시된 몇 가지 차이점이 있습니다. 단순한 `#42`는 트래커 구성에 따라 이슈 또는 PR로 해석하십시오.

트리아지 중에 이슈 트래커에 게시되는 모든 댓글이나 이슈는 **반드시** 다음 면책 문구로 시작해야 합니다.

```
> *This was generated by AI during triage.*
```

## 참조 문서

- [AGENT-BRIEF.md](AGENT-BRIEF.md): 지속적인 에이전트 브리프를 작성하는 방법
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md): `.out-of-scope/` 지식 베이스가 동작하는 방식

## 역할

두 가지 **범주** 역할:

- `bug`: 무언가가 망가짐
- `enhancement`: 새로운 기능 또는 개선

다섯 가지 **상태** 역할:

- `needs-triage`: 유지 관리자가 평가해야 함
- `needs-info`: 보고자의 추가 정보를 기다리는 중
- `ready-for-agent`: 완전히 명세되었으며, AFK 에이전트가 처리 가능
- `ready-for-human`: 사람의 구현이 필요함
- `wontfix`: 조치하지 않음

PR의 경우, 같은 상태가 첨부된 코드를 기준으로 해석됩니다. `ready-for-agent`는 브리프가 첨부되어 있으며 에이전트가 diff에 대해 다음 단계를 수행해야 한다는 의미이고, `ready-for-human`은 사람이 병합할 준비가 되었다는 의미입니다.

트리아지된 모든 이슈는 정확히 하나의 범주 역할과 하나의 상태 역할을 가져야 합니다. 상태 역할이 충돌한다면, 다른 무엇을 하기 전에 이를 지적하고 유지 관리자에게 물으십시오.

이것들은 표준 역할 이름입니다. 이슈 트래커에서 사용하는 실제 라벨 문자열은 다를 수 있습니다. 매핑은 이미 제공되었어야 합니다. 그렇지 않다면 사용자에게 `/setup-matt-pocock-skills`를 실행하라고 안내하십시오.

상태 전이: 라벨이 없는 이슈는 보통 먼저 `needs-triage`로 갑니다. 거기서 `needs-info`, `ready-for-agent`, `ready-for-human`, 또는 `wontfix`로 이동합니다. `needs-info`는 보고자가 답하면 `needs-triage`로 돌아갑니다. 유지 관리자는 언제든 이를 재정의할 수 있습니다. 비정상적으로 보이는 전이는 지적하고 진행하기 전에 물으십시오.

## 호출

유지 관리자는 `/triage`를 호출하고 원하는 것을 자연어로 설명합니다. 요청을 해석하고 행동하십시오. 예:

- "내 주의가 필요한 것을 보여 줘"
- "#42를 살펴보자"(이슈 또는 PR)
- "#42를 ready-for-agent로 옮겨 줘"
- "에이전트가 가져갈 준비가 된 것은 뭐야?"

## 주의가 필요한 것 보여 주기

이슈 트래커를 조회하여 세 개의 묶음을 오래된 것부터 제시하십시오.

1. **라벨 없음**: 한 번도 트리아지되지 않음.
2. **`needs-triage`**: 평가 진행 중.
3. **마지막 트리아지 노트 이후 보고자 활동이 있는 `needs-info`**: 재평가 필요.

PR이 범위에 포함되는 경우, 이 묶음에 외부 PR을 포함하고 각 줄에 `[PR]` 또는 `[issue]` 태그를 다십시오. 탐색은 *외부* PR만 드러내므로(누가 외부인인지는 트래커 구성이 정의합니다), 협업자의 진행 중인 PR은 트리아지 작업이 아닙니다. 이 필터는 탐색에만 적용됩니다. 명시적으로 지정된 PR은 작성자와 관계없이 항상 트리아지됩니다.

개수와 항목당 한 줄 요약을 보여 주십시오. 유지 관리자가 선택하도록 하십시오.

## 특정 이슈 또는 PR 트리아지

1. **컨텍스트를 수집하십시오.** 이슈나 PR 전체(본문, 댓글, 라벨, 작성자, 날짜, 그리고 PR의 경우 diff도)를 읽으십시오. 이미 해결된 질문을 다시 묻지 않도록 이전 트리아지 노트를 파싱하십시오. 프로젝트의 도메인 용어집을 사용하여 코드베이스를 탐색하고, 해당 영역의 ADR을 존중하십시오. 코드베이스를 대상으로 두 가지 검사를 실행하십시오. (a) **중복**: 요청된 동작의 기존 구현을 (요청의 문구만이 아니라) 도메인 개념으로 검색하고, 어디를 살펴보았는지 보고하십시오. 발견되면, 그것은 이미 구현된 `wontfix`입니다(5단계). (b) **이전 거절**: `.out-of-scope/*.md`를 읽고 이 요청과 유사한 것을 드러내십시오.

2. **권고하십시오.** 유지 관리자에게 범주와 상태에 대한 권고를 근거와 함께 알리고, 요청과 관련된 간략한 코드베이스 요약(이미 구현되어 있는지 여부 포함)을 제공하십시오. 지시를 기다리십시오.

3. **주장을 검증하십시오.** 그릴링하기 전에, 주장이 성립하는지 확인하십시오. 버그의 경우, 보고자의 단계를 따라 재현하십시오. PR의 경우, diff가 주장하는 바를 하는지 확인하십시오. 체크아웃하고, 관련 테스트나 명령을 실행하십시오. 무슨 일이 일어났는지 보고하십시오. 확인됨(코드 경로와 함께), 실패함, 또는 세부 정보 부족(강력한 `needs-info` 신호)입니다. 확인된 검증은 훨씬 더 강력한 에이전트 브리프를 만듭니다.

4. **그릴링하십시오(필요한 경우).** 요청을 구체화해야 한다면, "grilling"과 "domain-modeling"에 대해 각각 한 번씩 Skill 도구를 두 번 호출하고, 한 번에 한 라운드의 질문으로 그릴링하여 형태를 잡으십시오. 결정이 내려짐에 따라 도메인 용어를 다듬고 `GLOSSARY.md`/ADR을 즉석에서 업데이트하십시오.

5. **결과를 적용하십시오.**
   - `ready-for-agent`: 에이전트 브리프 댓글을 게시하십시오([AGENT-BRIEF.md](AGENT-BRIEF.md)).
   - `ready-for-human`: 에이전트 브리프와 같은 구조이지만, 왜 위임할 수 없는지(판단의 문제, 외부 접근, 설계 결정, 수동 테스트)를 기록하십시오.
   - `needs-info`: 트리아지 노트를 게시하십시오(아래 템플릿).
   - `wontfix`의 경우, *이유*에 따라 다른 댓글과 함께 이슈를 종료하십시오.
     - **이미 구현됨**: 변경이 이미 코드베이스에 존재합니다. 그것이 있는 곳을 가리키십시오. `.out-of-scope/`에 기록하지 **마십시오**(그 지식 베이스는 구축된 요청이 아니라 *거절된* 요청을 위한 것입니다).
     - **거절됨(버그)**: 정중한 설명을 제공한 다음, 종료하십시오.
     - **거절됨(개선)**: `.out-of-scope/`에 기록하고, 댓글에서 그것을 링크한 다음, 종료하십시오([OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)).
   - `needs-triage`: 역할을 적용하십시오. 부분적인 진전이 있다면 선택적으로 댓글을 다십시오.

## 빠른 상태 재정의

유지 관리자가 "#42를 ready-for-agent로 옮겨 줘"라고 말하면, 그를 신뢰하고 역할을 직접 적용하십시오. 무엇을 하려는지(역할 변경, 댓글, 종료) 확인한 다음, 행동하십시오. 그릴링은 건너뛰십시오. 그릴링 세션 없이 `ready-for-agent`로 옮기는 경우, 에이전트 브리프를 작성하기를 원하는지 물으십시오.

## Needs-info 템플릿

```markdown
## 트리아지 노트

**지금까지 확인된 사항:**

- 요점 1
- 요점 2

**아직 필요한 사항 (@reporter):**

- 질문 1
- 질문 2
```

작업이 사라지지 않도록, 그릴링 중에 해결된 모든 것을 "지금까지 확인된 사항" 아래에 기록하십시오. 질문은 "더 많은 정보를 제공해 주십시오"가 아니라 구체적이고 실행 가능해야 합니다.

## 이전 세션 재개

이슈나 PR에 이전 트리아지 노트가 있다면, 그것을 읽고, 보고자가 미해결 질문에 답했는지 확인하고, 계속하기 전에 업데이트된 상황을 제시하십시오. 이미 해결된 질문을 다시 묻지 마십시오.
