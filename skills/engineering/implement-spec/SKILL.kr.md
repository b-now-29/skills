명세가 제공되었습니다. 이 명세에는 그것을 어떻게 구현할지 기술하는 티켓들이 연결되어 있어야 합니다.

이슈 트래커는 이미 제공되었어야 합니다. 그렇지 않다면 사용자에게 `/setup-matt-pocock-skills`를 실행하라고 안내하십시오.

목표는 명세 전체를 하나의 **통합 브랜치(integration branch)**에 구현하고, 모든 티켓을 이슈 트래커가 작업을 종료하는 방식대로 해결하는 것입니다.

티켓은 단계의 목록이 아닙니다. 티켓 간에 차단 관계가 있는 **작업 그래프(task graph)**입니다. 이는 언제나 가져갈 준비가 된 티켓의 **전선(frontier)**이 존재한다는 것을 의미합니다.

모든 서브에이전트는 새로운 컨텍스트 윈도우로 시작하십시오.

서브에이전트와의 소통은 간결해야 합니다. 주로 **컨텍스트 포인터**를 통해 소통하십시오. 명세, 티켓, 조사 노트, 이전 커밋을 가리키는 포인터입니다. 포인터를 통해 이미 얻을 수 있는 정보를 중복하지 마십시오.

**구현자 서브에이전트**는 최대 동시성을 위해 가능한 한 백그라운드에서 실행해야 합니다.

## 단계

1. 명세와 티켓을 읽고 작업 그래프를 이해하십시오.

2. (선택 사항) 티켓이 요구하는 탐색(관련 코드베이스 파일 또는 외부 문서)을 수행하기 위해 **탐색 서브에이전트**를 사용하십시오. 탐색 서브에이전트가 파일을 저장할 수 있도록 하십시오. 탐색 서브에이전트는 이후의 모든 서브에이전트가 접근할 수 있는, 저장소 외부의 디렉터리에 마크다운 노트를 저장해야 합니다. 이렇게 하면 **구현자 서브에이전트**가 탐색이 아니라 구현에 집중할 수 있습니다.

3. 통합 브랜치를 생성하십시오. 이슈 트래커가 PR을 통해 작업을 종료하거나 사용자가 PR을 요청하는 경우, 5단계의 첫 번째 병합 후에(main보다 앞선 커밋이 없는 브랜치는 PR을 열 수 없습니다) 명세와 티켓을 종료하는 것으로 표시된 초안 PR을 여십시오.

4. 티켓마다 새로운 **구현자 서브에이전트**를 사용하며, 각각 자체 브랜치의 자체 워크트리에서 작업합니다. 각 구현자 서브에이전트는 다음을 수행합니다.
   - 시작하기 전에 워크트리가 통합 브랜치를 기반으로 하는지 확인하고, 그렇지 않다면 통합 브랜치로 재설정합니다.
   - 티켓을 구현하기 위해 `tdd`로 Skill 도구를 호출합니다.
   - 완료를 보고하기 전에 통합 브랜치의 최신 커밋을 자신의 브랜치에 병합합니다.

5. **구현자 서브에이전트**가 완료되면, **병합 서브에이전트**로 그 작업을 통합 브랜치에 병합하십시오.

6. 이로 인해 사용 가능한 티켓의 **전선**이 바뀌면, 새 티켓을 처리할 **구현자 서브에이전트**를 추가로 시작하십시오. 이렇게 하면 최대 동시성을 얻을 수 있습니다.

7. 모든 티켓이 완료되면, 통합 브랜치에 대해 `code-review`로 Skill 도구를 호출하십시오. 코드 리뷰가 제기한 모든 문제를 하나의 새로운 **구현자 서브에이전트**에서 수정하십시오.

8. 초안 PR이 존재한다면, 리뷰 준비 완료로 표시하십시오. 그렇지 않다면, 각 티켓을 이슈 트래커가 작업을 종료하는 방식대로 해결하고, 통합 브랜치를 보고하십시오.

9. 모든 **구현자 서브에이전트** 워크트리를 정리하십시오.
