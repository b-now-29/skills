# 마법사

**마법사(wizard)**는 손으로 하기에도 지루하고 매번 AI에게 다시 설명하기에도 지루한 수동 절차를, 사람에게 단계별로 안내하는 bash 스크립트입니다. 각 URL을 열고, 무엇을 클릭하고 복사해야 하는지 정확히 알려 주고, 값을 받아, 그 값이 있어야 할 곳(`.env`, GitHub 시크릿)에 기록하며, 매 단계마다 확인하고, 남은 단계가 몇 개인지 보여 줍니다. 서드파티 서비스를 구성하거나, 일회성 마이그레이션을 실행하거나, 프로젝트를 한 상태에서 다른 상태로 옮길 수 있습니다.

쾌적한 UX는 이미 [template.sh](template.sh)가 해결해 두었습니다. 단계별 진행 상황, 확인 관문, 크로스 플랫폼 URL 열기(WSL 포함), 숨겨진 시크릿 입력, 멱등적인 `.env` upsert, `gh secret`/`gh variable` 쓰기, 그리고 마무리 요약입니다. **당신의 일은 절차의 범위를 정하고 그 단계들을 작성하는 것뿐입니다.** `STAGES` 표시 위의 라이브러리는 모든 마법사에서 동일합니다. 그 일관성이 요점입니다. 절대 손으로 편집하지 마십시오.

마법사는 기본적으로 일시적입니다. 한 번의 실행을 위해 만들어지며, 임시 경로나 `scripts/` 경로에 저장되고, 작업이 끝나면 삭제됩니다. 사용자가 저장소에 있어야 할 반복 가능한 설정 경로를 원할 때만 커밋하십시오.

## 프로세스

### 1. 절차의 범위 정하기

사람이 수행해야 하는 모든 수동 단계와 그 과정에서 받는 모든 값을 파악하십시오. 무작정 묻지 말고 먼저 저장소를 읽으십시오.

- 설정의 경우: `.env`, `.env.example`, `.env.*`, `README`, `docker-compose*`, 프레임워크 구성, 그리고 `.github/workflows/*`(모든 `secrets.*` / `vars.*` 참조는 마법사가 만들어 내야 하는 값입니다).
- 마이그레이션이나 전환의 경우: 현재 상태, 목표 상태, 그리고 그 사이의 되돌릴 수 없는 작업.

그런 다음 사용자에게 순서가 정해진 단계 목록과 각 단계가 만들어 내는 값을 보여 주고 확인하십시오. 사용자는 추가하거나, 빼거나, 순서를 바꿀 수 있습니다.

**완료 조건:** 모든 단계의 이름이 순서대로 정해졌고, 받는 각 값에 대해 (a) 사람이 어디서 그 값을 얻는지, (b) 어디에 기록되는지(`.env`, GitHub 시크릿, 둘 다, 또는 어디에도 기록되지 않음. 일부 단계는 순수한 작업입니다), (c) 시크릿인지(숨겨진 입력) 공개 값인지를 알고 있습니다.

### 2. 각 단계의 여정 그리기

각 단계에 대해 사람이 따르는 정확한 경로를 작성하십시오. 어떤 URL을 열지, 거기서 무엇을 할지, 값이 어디에 표시되는지, 그 값이 어떤 변수를 채우는지입니다. 예: "대시보드 → Developers → API keys → Reveal test key → 복사". 현재 UI나 정확한 명령을 실제로 알지 못하는 경우, 그렇다고 말하고 사용자에게 묻거나 문서를 확인하십시오. 존재하지 않을 수도 있는 단계를 절대 지어내지 마십시오.

**완료 조건:** 모든 단계가 처음 보는 사람도 따를 수 있는 구체적인 지시로 이어집니다.

### 3. 마법사 작성하기

`template.sh`를 대상 경로로 복사하십시오. 예시 단계를 의존성 순서에 따라 단계마다 하나의 `stage`로 교체하십시오. 라이브러리 도우미를 사용하십시오: `stage`, `say`/`step`, `open_url`, `ask`/`ask_secret`, `write_env`, `set_secret`/`set_var`, `pause`/`confirm`. `TOTAL_STAGES`를 작성한 단계 수로 설정하십시오.

템플릿이 정한 기준을 지키십시오. 값을 묻기 전에 URL을 열고, 시크릿인 것은 모두 `ask_secret`을 사용하고, 보존되는 모든 값은 `write_env`하고, CI가 실제로 필요로 하는 값만 `set_secret`하며, 되돌릴 수 없는 작업 전에는 `confirm`하십시오. 각 `stage`는 화면을 지우므로 현재 단계만 보입니다. 사람이 필요로 하는 것이 스크롤되어 사라지지 않도록, 하나의 단계는 하나의 집중된 작업으로 유지하십시오. 표시 위의 라이브러리는 건드리지 마십시오.

### 4. 검증 및 인계

- `bash -n <script>`. 가능하다면 `shellcheck`를 실행하십시오.
- `chmod +x <script>`.
- 직접 처음부터 끝까지 실행하지 마십시오. 브라우저를 열고 사람의 입력을 기다리며 멈춥니다. 대신 정적으로 추적하십시오. 1단계의 모든 값이 받아지고 1단계에서 말한 곳에 기록되며, 모든 `set_secret` 이름이 CI의 `secrets.*` 참조와 정확히 일치하는지 확인하십시오.
- 사용자에게 실행 방법을 알려 주십시오. 반복 가능한 설정 경로라면, 커밋하고 README에서 링크하여 다음 사람이 AI에게 묻는 대신 스크립트를 실행하도록 하십시오.
