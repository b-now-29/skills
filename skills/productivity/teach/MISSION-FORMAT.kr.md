# MISSION.md 형식

`MISSION.md`는 작업 공간의 루트에 위치합니다. 사용자가 이 주제를 배우는 _이유_를 담습니다. 모든 교육 결정(다음에 무엇을 가르칠지, 어떤 자료를 제시할지, 어떤 연습 문제를 설계할지)은 이 문서로 거슬러 올라갈 수 있어야 합니다.

## 템플릿

```md
# 미션: {주제}

## 이유
{1~3문장. 사용자가 추구하는 구체적인 실제 목표. 이 기술을 갖추면 사용자의 삶이나 일에서 무엇이 바뀝니까? "X를 이해하기 위해"와 같은 추상적인 표현은 피하고, 근본적인 결과를 이끌어 내십시오.}

## 성공의 모습
- {사용자가 할 수 있게 될 구체적이고 관찰 가능한 일}
- {또 다른 구체적인 일}
- {…}

## 제약 조건
- {시간, 예산, 기존 약속, 학습 선호도 등 접근 방식을 제한하는 모든 것}

## 범위 외
- {사용자가 지금은 명시적으로 다루고 싶지 않은 인접 주제로, 근접 발달 영역을 보호함}
```

## 규칙

- **작업 공간당 하나의 미션.** 사용자가 서로 관련 없는 두 가지를 배우고 싶다면, 그것은 두 개의 작업 공간입니다.
- **추상적인 것보다 구체적인 것.** "10월까지 하프 마라톤 완주하기"가 "더 건강해지기"보다 낫습니다. "팀에 Rust CLI 배포하기"가 "Rust 배우기"보다 낫습니다.
- **모호함에 이의를 제기하십시오.** 사용자가 이유를 명확히 말하지 못한다면, 무엇이든 작성하기 전에 인터뷰하십시오. 나쁜 미션은 미션이 없는 것보다 나쁩니다.
- **현실이 바뀌면 수정하십시오.** 미션은 바뀝니다. 사용자의 목표가 이동하면 이 파일을 업데이트하십시오. 낡은 미션이 향후 세션을 이끌도록 두지 마십시오.
- **짧게 유지하십시오.** `MISSION.md`가 한 화면을 넘어가면, 그것은 나침반이기를 멈추고 계획이 되기 시작한 것입니다.
