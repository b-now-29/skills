# 예시 작업

해결하는 문제별로 묶은 작업입니다. 각 작업은 실행을 시작하는 트리거, 실행이 하는 일, 그리고 다음에 트리거하는 것을 명시합니다. 대부분의 팩토리는 이들 중 하나로 시작하여 다음 작업을 연결하며 성장합니다.

## 트리아지되지 않은 티켓이 쌓인다

**탐색 작업(Explore task)**
- 트리거: 티켓이 생성되거나, 사람이 라벨을 붙입니다.
- 하는 일: 코드베이스를 기준으로 티켓을 확인하고 범주(쉬운 판단, 사람이 필요함, 버그 아님)로 분류합니다.
- 트리거하는 것: 쉬운 판단에 대해서는 구현자 실행. 그 밖의 경우는 티켓에 사람을 기다리는 중이라는 라벨을 붙이고 종료합니다.

## 준비된 티켓이 누군가 만들어 주기를 기다린다

**구현자 작업(Implementer task)**
- 트리거: 사람이나 탐색 실행에 의해 티켓에 준비 완료 라벨이 붙습니다.
- 하는 일: 자동화된 검사가 통과할 때까지 티켓을 구현하고, 초안 PR을 엽니다.
- 트리거하는 것: 자동화된 리뷰 실행.

## PR이 리뷰를 기다린다

**자동화된 리뷰 작업(Automated review task)**
- 트리거: 아직 자동화된 리뷰가 없는 PR이 열리거나, 사람이 라벨을 붙입니다.
- 하는 일: 코드베이스의 표준과 PR의 출처인 티켓을 기준으로 diff를 리뷰합니다.
- 트리거하는 것: 실패 시 재작업 실행. 통과 시 종료되며, PR은 사람이 병합하기 전에 사람의 리뷰를 기다립니다.

## 실패한 자동화된 리뷰가 수정되지 않은 채 방치된다

**재작업 작업(Rework task)**
- 트리거: 자동화된 리뷰 실행이 PR을 실패 처리합니다.
- 하는 일: 자동화된 리뷰가 지적한 것만 수정하고, 푸시합니다.
- 트리거하는 것: 자동화된 리뷰 실행. 정해진 횟수만큼 실패하면, PR에 사람을 기다리는 중이라는 라벨을 붙이고 종료합니다.

## 명세가 한 번의 실행으로 처리하기에는 너무 크다

**분해 작업(Decompose task)**
- 트리거: 명세 티켓에 라벨이 붙습니다.
- 하는 일: 명세를 티켓으로 분할하며, 각 티켓은 자신이 의존하는 티켓을 기록합니다.
- 트리거하는 것: 구현자 실행.

이 경우 구현자 실행은 의존하는 티켓이 모두 종료된 다음 티켓을 선택하며, 남은 티켓이 없을 때까지 스스로를 다시 트리거합니다.

## 더 엄격한 자동화된 검사로 마이그레이션하기

새로운 린트 규칙(또는 더 엄격한 타입 설정)이 활성화되었지만, 일부 파일만 이를 통과합니다. 규칙은 통과하는 파일에 강제되고, 실패하는 파일은 예외 목록에 올라 있습니다.

**래칫 작업(Ratchet task)**
- 트리거: 매일 울리는 시계.
- 하는 일: 예외 목록에서 파일 하나를 꺼내, 더 엄격한 검사가 통과할 때까지 수정하고, PR을 엽니다.
- 트리거하는 것: 자동화된 리뷰 실행. 예외 목록이 비면, 래칫 실행은 꺼낼 것이 없으며 마이그레이션이 완료됩니다.

하루에 하나의 작은 PR은 사람의 리뷰 비용을 낮게 유지하며, 검사는 오직 더 엄격해지기만 합니다.

## 사용자가 아무도 읽지 않는 버그를 보고한다

앱의 피드백 버튼은 티켓 소스입니다. 각 보고서를 탐색 라벨이 이미 붙은 티켓으로 제출합니다. 나머지는 탐색 실행이 처리합니다.

## 프로덕션 문제가 늦게 발견된다

모니터(느린 쿼리, 오류율)는 티켓 소스입니다. 문제마다 티켓을 하나씩 제출하며, 같은 문제를 다시 보면 대신 열려 있는 티켓에 댓글을 답니다. 수정이 병합된 후에도 문제가 지속되면, 티켓을 다시 엽니다.

## 팩토리 자체의 실행이 실패한다

**수정 작업(Fix task)**
- 트리거: 오케스트레이터가 실패한 실행을 보고합니다.
- 하는 일: 실패한 로그를 티켓으로 제출하고, 실패가 수정 가능한 경우 PR로 수정을 시도합니다.
- 트리거하는 것: 자동화된 리뷰 실행. 수정 실행 자체의 작업에서 발생한 실패는 아무것도 트리거하지 않으므로, 수정이 연쇄되지 않습니다. 수정은 팩토리 자체를 변경하므로, 항상 사람의 리뷰를 받습니다.

## 코드베이스가 표류한다

**아키텍처 작업(Architecture task)**
- 트리거: 매일 밤 울리는 시계.
- 하는 일: 최근 변경 사항에서 리팩터링 후보를 탐색하고 하나의 티켓으로 제출합니다.
- 트리거하는 것: 없음. 사람이 후보를 선택하고 라벨을 붙이면, 일반적인 연쇄가 시작됩니다.

## 같은 실수가 계속 반복된다

**회고 작업(Retro task)**
- 트리거: PR이 병합되며, 병합된 PR 열 개 중 하나로 조절됩니다.
- 하는 일: PR, 해당 티켓, 자동화된 리뷰, 실행 로그를 읽고, 팩토리 자체의 지침에 대한 변경을 PR로 제안합니다.
- 트리거하는 것: 자동화된 리뷰 실행.
