# 모델 호출 대 사용자 호출

이 저장소의 모든 `SKILL.md`는 스킬입니다. 이들을 구분하는 유일한 축은 **호출(invocation)**, 즉 누가 해당 스킬에 도달할 수 있는가입니다.

- **사용자 호출(User-invoked)**: **사람이 이름을 직접 입력해야만** 도달할 수 있습니다. 프런트매터에 `disable-model-invocation: true`(Claude Code)를, `agents/openai.yaml`에 `policy.allow_implicit_invocation: false`(Codex)를 설정합니다. `description`은 **사람을 위한** 것으로, 슬래시 명령을 둘러보는 사람이 읽는 한 줄 요약입니다. 트리거 목록("사용자가 …라고 말할 때 사용")은 제거하십시오.
- **모델 호출(Model-invoked)**: **모델 또는 사용자**가 도달할 수 있습니다. 기본값입니다. `disable-model-invocation`과 `agents/openai.yaml`의 `policy` 블록을 생략합니다. `description`은 **모델을 위한** 것으로, 자동 호출이 동작하도록 풍부한 트리거 문구("사용자가 …을 원할 때, …을 언급할 때, …을 요청할 때 사용")를 유지합니다. 스킬을 모델 호출로 유지해야 하는지에 대한 판단 기준은 다음과 같습니다. _모델이 이 스킬을 자율적으로 사용하는 것이 유용한가?_ (재사용성은 스킬을 추출하는 이유이지, 판단 기준이 아닙니다.)

각 하네스는 고유한 방식으로 사용자 호출 스킬을 모델의 접근 범위에서 제외하므로, 사람 외에는 아무도 이를 실행할 수 없습니다. 다른 스킬도 실행할 수 없습니다. 사용자 호출 스킬은 모델 호출 스킬을 호출할 수 있지만, 다른 사용자 호출 스킬에는 결코 도달할 수 없습니다.

모든 스킬은 `SKILL.md` 옆에 `agents/openai.yaml`도 함께 가집니다. 이 파일은 Codex UI 메타데이터를 담고 있습니다. 즉, 스킬 선택기를 위한 `interface.display_name`과 `interface.short_description`, 그리고 사용자 호출 스킬의 경우 `disable-model-invocation`과 짝을 이루는 `policy.allow_implicit_invocation: false`입니다. 두 값을 동기화된 상태로 유지하십시오. 스킬은 두 하네스 모두에서 사용자 호출이거나, 둘 다 아니어야 합니다.

버킷 `README.md`와 최상위 `README.md`는 항목을 **사용자 호출**과 **모델 호출**로 그룹화합니다.

## 둘 사이의 의존성

의존성은 지정된 스킬로 **Skill 도구를 호출**하라는 명시적인 지시(`Call the Skill tool with "grilling"`)로 표현합니다. 깊은 `../other-skill/FILE.md` 상호 참조나, 모델이 해석하도록 남겨 둔 단순한 `/skill` 형식의 언급으로 표현하지 않습니다. 도구를 명시하는 것이 실제로 실행되게 만드는 방법입니다. 대부분의 하네스는 스킬 호출을 모델이 호출하는 도구로 노출하며, 이를 명확히 기술하는 것이 서술 중에 `/name`을 넣고 명령으로 읽히기를 기대하는 것보다 적중률이 높습니다. 앞의 `/`를 빼면 하네스 중립성도 높아집니다. 스킬 이름 자체에는 어떤 하네스의 트리거 문법에 속하는지에 대한 가정이 담기지 않기 때문입니다. 공유 참조 문서는 이를 소유하는 스킬 내부에 둡니다. 다른 스킬은 폴더 간 링크가 아니라 해당 스킬로 Skill 도구를 호출하여 그 내용에 접근합니다.

이는 **실행적(operative)** 지시에 관한 것입니다. 즉, 스킬 자체의 단계가 에이전트에게 지금 바로 다른 스킬을 실행하라고 지시하는 경우입니다. 사람이 선택하도록 스킬 이름만 나열하는 라우터 서술(`ask-matt`, 버킷 `README.md`)은 아무것도 호출하지 않으므로, `/skill` 형식의 이름을 단순한 라벨로 유지합니다.

Skill 도구는 호출당 하나의 스킬을 받습니다. 두 개의 스킬이 필요한 단계는 두 개의 이름을 가진 한 번의 호출이 아니라 두 번의 호출입니다. "X와 Y로 호출하라"처럼 둘 다 받는 한 번의 호출로 읽히는 표현 대신, 그렇게 명시하십시오(`Call the Skill tool twice, for "grilling" and "domain-modeling"`).

이 규칙 전체는 지정된 스킬이 **모델 호출**인 경우에만 성립합니다. 사용자 호출 스킬은 어떤 경우에도 이 방식으로 도달할 수 없습니다. 위의 불변 조건에 따라, Skill 도구에 이름을 지정하는 방식을 포함하여 어떤 다른 스킬도 이를 호출할 수 없습니다. 어떤 단계의 전제 조건이 사용자 호출 스킬(예: `setup-matt-pocock-skills`)인 경우, Skill 도구 호출이 아니라 사람이 수행할 지시로 표현하십시오. 예: "사용자에게 `/setup-matt-pocock-skills`를 실행하라고 안내하십시오."

## 수동적 도메인 작업 대 능동적 도메인 작업

어휘를 위해 `GLOSSARY.md`를 단순히 _읽는_ 것은 한 줄짜리 서술 안내이며, `domain-modeling` 스킬이 아닙니다. 능동적인 구축/정제 규율(용어에 이의 제기, 엣지 케이스 시나리오, ADR 작성, `GLOSSARY.md`를 즉석에서 업데이트)만이 `domain-modeling`입니다.
